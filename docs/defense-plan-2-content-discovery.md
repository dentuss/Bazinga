## 0:00 · Вступ (≈45 c)

**👉 На екрані:** головна сторінка `/comics`, видно ряди коміксів і манги.

Я як Full-Stack відповідав за **весь контент платформи**: каталог коміксів, манги,
персонажів і потокове відео BazingaTV.

**Важливий контекст — куди це йде далі.** У продакшні Bazinga
працюватиме поверх **редакційної (ліцензованої) бази контенту**: справжні комікси,
манга й аніме надходитимуть від правовласників через окрему публікаційну БД. Тому
**окрема адмін-панель для ручного наповнення контенту тут не потрібна** —
її роль виконує редакційна сторона. Поки що, на етапі прототипу, реальний контент
**замінений на метадані з відкритих джерел** — це і дозволяє показати готовий каталог,
картки, описи, обкладинки, не маючи власних прав на тайтли.

Тобто архітектурно я будував **той самий каталог, що буде у живій версії** —
просто з підмінним джерелом.

## Блок 1 · Агрегатор метаданих (≈2:45)

**👉 На екрані:** прокрутити `/comics` — показати ряд «MANGA», потім перейти у хедері
на `Manga` → `/manga`, потім на `Characters` → `/characters`.

Власної редакційної бази на тисячі тайтлів немає, тому я інтегрував **три повністю
безкоштовні API без авторизації** (це окремо була складна задача — більшість галузевих
API платні або вимагають підпису кожного запиту):

- **Jikan v4** (MyAnimeList) — аніме + манга
- **akabab/superhero-api** — ~731 персонаж коміксів (Marvel, DC, Dark Horse…)
- **TVMaze** — серіали (для блоку Superhero Shows на BazingaTV)

**👉 На екрані:** залишитись на `/characters`, показати — це реальні Marvel/DC персонажі
з обкладинками та біографіями.

**Єдина точка входу для клієнта** — `bazinga.api/.../Controllers/MetadataController.cs`
(16 ендпоінтів):
- аніме: `top` **24**, `search` **45**, `genres` **64**
- манга: `top` **69**, `search` **76**
- персонажі: `superheroes` **99**, `publishers` **109**
- серіали: `superhero-shows` **122**, `search` **126**

**Два сервіси за інтерфейсами** (Dependency Inversion):
- `Services/JikanService.cs` — аніме/манга
- `Services/SuperheroService.cs` — персонажі (akabab) + серіали (TVMaze)

> Деталь: жанри й теми Jikan об'єдную в один список; для манги додатково виключаю
> «дорослі» жанри — `JikanService.cs:77` (`MangaExcludedGenres = "9,12,28,30,49"`) +
> застосування на **100**, щоб на головній не з'являлось NSFW.

## Блок 2 · Кешування + продуктивність (≈2:00)

**👉 На екрані:** на `/characters` поклацати чипи видавців (Marvel → DC → Image) —
звернути увагу комісії на **миттєву реакцію без запитів у мережу**. Потім — натиснути
«Next» у пагінаторі.

Зовнішні API мають ліміти (Jikan — 3 запити/сек), тож усе кешується в пам'яті через
`IMemoryCache` (Cache-Aside pattern).

Код — `Services/JikanService.cs`:
- TTL списків — 15 хв: **рядок 10**; деталі — кеш на **58, 107**
- **generic-метод проти дублювання коду** `GetPagedCached<TRaw,TDto>`: використання **29–53**

`Services/SuperheroService.cs` — ключова оптимізація, яку ми щойно бачили на екрані:
- весь датасет akabab (~1 МБ, 731 запис) тягнеться **один раз** і кешується на 12 год:
  **рядки 20, 118**
- далі пошук / фільтр / пагінація працюють **по пам'яті**, без жодного зовнішнього
  запиту — саме тому перемикання видавців миттєве: **рядки 58–108**
- серіали TVMaze: куратований набір з 27 запитів, об'єднання + дедуплікація, кеш 6 год:
  **рядки 26, 174**

**Сервіс ціноутворення** (залежить від типу підписки) — `Services/PricingService.cs:7`.
Він наживо враховує, що користувач з тарифом Unlimited читає цифрову копію безкоштовно.

## Блок 4 · BazingaTV + найскладніша проблема (≈1:30)

**👉 На екрані:** у хедері натиснути **TV** → `/bazinga-tv`. Показати hero-каруселю,
що сама перемикає трейлери випадковими шматочками. Потім клікнути «Play» на одному
з шоу — відкриється повноекранний плеєр `/bazinga-tv/watch/...`. Закрити, повернутись.

`components/TVHero.tsx`:
- hero-карусель програє трейлери **випадковими фрагментами по 10–15 c**: **рядки 12–13, 32–38**
- повноекранний HTML5-плеєр — `pages/Watch.tsx`

**Найскладніша проблема — пошук безкоштовних API метаданих** (саме те, з чого
починалась моя частина). Marvel API вимагає ключ + MD5-підпис кожного запиту,
ComicVine/TMDB — реєстрацію, Marvel Metadata API — взагалі без обкладинок. Рішення:
зупинився на трьох no-auth джерелах (Jikan / akabab / TVMaze), кожне з graceful-fallback
(помилка → лог + порожній список, сервіс не падає): `SuperheroService.cs:118`.

**Друга проблема — зламані обкладинки коміксів.** Vite-asset шляхи (`/assets/...`)
йшли через `API_URL` → 404. Виправив у `lib/images.ts` (пропуск Vite-шляхів) +
fallback-градієнт у `MediaCard`.

## Можливі питання (підготуватись)

- **Чому немає адмін-панелі для контенту?** У продакшні контент приходить з редакційної
  ліцензованої БД (Marvel/DC/MAL-партнерства тощо). Ручне адміністрування на нашому боці
  не потрібне за дизайном; ми зосередились на користувацькому каталозі. На прототипі
  реальний контент замінений метаданими — це доводить, що каталог працює.
- **Чому саме ці три API?** Безкоштовні, без авторизації, з обкладинками. Платні/ключові
  (Marvel, ComicVine, TMDB) відкинуті свідомо.
- **Що буде, якщо Jikan/akabab лежить?** Кеш + graceful-fallback (порожній список, лог);
  сторінка не падає (`SuperheroService.cs:118`).
- **Навіщо `GetPagedCached<TRaw,TDto>`?** Прибирає дублювання між десятком майже однакових
  методів аніме/манги; типобезпечно.
- **Як працює пошук одразу по трьох джерелах?** Дебаунс 250 мс, три паралельні запити,
  результати згруповані; клік відкриває модалку in-place.
- **Чому akabab тягнеться весь одразу?** Це статичний файл ~1 МБ; один fetch + 12 год
  кешу дешевше, ніж посторінкові запити, і знімає залежність від доступності джерела.
- **Як легко буде підставити справжню ліцензовану БД?** Тільки замінити реалізації
  `IJikanService` і `ISuperheroService` на нові, що читають з нашої БД (через EF Core).
  Контролери і весь клієнтський UI лишаються незмінними — це і є сенс розділення
  через інтерфейси.
